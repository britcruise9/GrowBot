# ADR 0001: React Native and Expo for the native creature

- Status: accepted for MVP 1
- Date: 2026-08-14

## Decision

Build the shared iOS and Android experience with React Native, Expo development
builds, Expo Router, and TypeScript. Put platform behavior in small Expo Modules written
in Swift and Kotlin when the shared APIs cannot express the required contract.

## Why

GrowBot already has meaningful JavaScript behavior, and the creature rules should not
be rewritten twice. React Native preserves one product implementation while retaining
direct access to native speech, audio, sensors, networking, and lifecycle behavior.
Expo owns repeatable project generation and dependency integration without limiting us
to Expo Go.

Flutter would require a Dart rewrite and still need native channels. Separate SwiftUI
and Compose apps would duplicate the UI and make domain drift likely. The chosen stack
keeps the creature logic portable and makes native code an explicit, narrow edge.

## Consequences

The native projects are generated by `expo prebuild` and are not committed. CI must
compile both generated platforms. A feature belongs in shared TypeScript unless it is
actually platform-specific; native adapters must expose a small behavioral contract.
